## Repository Security Constraints

### Secrets and Data Handling

- Never read or print `.env`, provider keys, Pi auth files, browser state, or unrelated user files.
- Never add credentials to source code, fixtures, tests, logs, or documentation.
- Treat `leadId` as untrusted input.
- Keep event payloads free of secrets and unnecessary personal data.

### Tool and Process Permissions

- The Pi session may call only explicitly allowlisted custom tools.
- Do not enable Pi filesystem or shell tools in the production session.
- Do not give the model broad `bash`, filesystem, CRM, or deployment access.
- Do not publish or deploy from Codex without the user explicitly requesting it.

### External Writes and Approval

- External writes require an approval record. This starter never sends a message.
- Never add a network-writing tool without an explicit approval gate and idempotency key.

## Change Security Checks

A completed change must:

- Introduce no secret or unapproved external side effect.
- Preserve tool allowlists and process permissions unless an explicitly authorized change requires otherwise.
- Preserve approval boundaries for every external write.
- Keep logs and events free of secrets and unnecessary personal data.
- Identify any logging or data-retention change during diff review.
